# 架构说明

## Goal

根据网表和元件选型，在洞洞板格点上完成物理元件映射、3D 正面布局、反面走锡布线、跳线规划和透视检查。

## Layers

### Import Layer

位置：`backend/app/importers`

职责：

- 解析 BOM、选型表、SPICE netlist、Multisim netlist report。
- 将外部文件转换为统一 Circuit IR。
- 保留 `.ms14` 增强导入器接口。

### Circuit IR

位置：`packages/circuit-ir`

职责：

- 定义 logical symbols、physical parts、nets、pins、routes、jumpers、warnings。
- 保证导入、映射、布局、布线和导出使用同一模型。

### Part Resolver

位置：`backend/app/part_resolver`

职责：

- 将 U1A/U1B 这类逻辑单元映射到 U1 物理器件。
- 根据器件库补齐封装、物理引脚、电源脚和未使用单元信息。

### Layout

位置：`backend/app/layout`

职责：

- 根据连接关系和封装尺寸生成初始摆放。
- 输出元件格点坐标、旋转、锁定状态和占孔信息。

### Routing

位置：`backend/app/routing`

职责：

- 将洞洞板抽象为格点图。
- 优先搜索底面走锡路径。
- 路径失败时生成跳线。
- 后续扩展 rip-up and reroute、多网络优先级和拥挤度成本。

### Renderer

位置：`packages/renderer-3d` 和 `apps/web`

职责：

- 渲染洞洞板、孔位、元件、反面走锡、跳线和网络高亮。
- 支持正面、反面、透视、爆炸视图。
- 支持拖动、旋转、吸附、锁定元件。

## 3D Component Model Strategy

本项目不追求每个具体芯片型号的真实 3D 外观。3D 元件采用“封装大类参数化模型”：

- 电阻、电容、电感、二极管、LED 等按器件大类生成。
- IC 按 DIP-8、DIP-14、DIP-16 等封装大类生成。
- 三极管、稳压管等按 TO-92 等封装大类生成。
- 排针、接线端子、按键、电位器等按可参数化封装生成。

器件知识库和 3D 模型库分离：

```text
器件知识库：
型号 -> 功能类型 -> 引脚数 -> 封装类别 -> 引脚功能映射

参数化模型库：
封装类别 + 参数 -> 3D 外观 + 洞洞板占孔 + 引脚坐标
```

示例：

```text
LM393 -> dual comparator -> DIP-8 -> pin map
DIP-8 -> black IC body + 8 pins + notch + pin-1 marker
```

这样可以避免第三方模型许可证和格式转换问题，并保证引脚坐标与洞洞板格点严格对齐。

### Desktop Shell

位置：`apps/desktop`

职责：

- 将 Web UI 和本地后端封装成 EXE。
- 后续在 Electron 或 Tauri 中二选一。
