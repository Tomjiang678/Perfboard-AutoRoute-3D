# 用户元件库与自定义建模（设计草案）

> 状态：设计草案，未实现，不排期。
> 目标：用户库和公用库最终是同一套东西；用户能自己定义脚数、脚位、脚距、外形，点一下就能放置。
> 关联：`Multisim导入支持计划.md`（`PinProfile` 的来源）、`apps/web/src/features/project/componentLibrary.ts`、`apps/web/src/renderer3d/parametricComponents.ts`

---

## 1. 结论先行

1. **不要造通用编程语言。** 设计一套声明式的「元件描述清单」（Component Description Manifest，下称 **CDM**）：JSON + 少量生成器，能被校验、diff、AI 生成、人工审核。它不是图灵完备的，也不执行任意代码。
2. **电气和几何分开。** 现有的 `PinProfile` 负责「Multisim 逻辑脚 → 物理脚号」；CDM 负责「物理脚在板上的位置 + 外形 + 高度」。两者用 `型号 + 封装` 关联，不重复存映射。
3. **脚必须落在 2.54 mm 网格孔上。** 这是洞洞板的硬约束。非 2.54 mm 间距的封装（SOIC/QFP）不能直接放，要么做转接板，要么只作为“外形参考”而不参与落板。
4. **公用库和用户库同 schema。** 内置元件未来也迁移成 CDM；用户条目只是 `source: "user"`。点击 LM324 → 生成 14 脚 DIP 的 CDM → 放置，走的是同一条渲染/校验路径。
5. **AI 只负责写 JSON。** 给 AI 一个固定 schema、坐标规则和示例，让它输出 CDM；软件校验、预览、报错。这样比让 AI 写代码可控得多。
6. **可视化编辑器是主路径，AI 是加速器。** 画矩形、点孔位、自动编号，比描述给 AI 更直接；AI 用来处理“脚很多、排列规律”的情况。

## 2. 现状（代码事实）

现在一个可放置元件由 `LibraryComponentDefinition` 描述：

```
kind / label / title / pinCount / leadSpacing / rowSpacing / sameSidePitch
pinHeaderRows / pinHeaderColumns / pinOffsets / adapter
```

- `pinOffsets` 是整数网格坐标数组，`PlacedComponent` 直接存它；放置、DIP 跨中缝、孔位占用、布线的端点都依赖它。
- 几何目前由 `kind` 参数化生成（电阻、TO-92、DIP、排针、转接板……），`getLibraryComponentByKind` 只能对少数 kind 动态生成脚数。
- 3D 由 `parametricComponents.ts` 按 `kind` 画，没有任意外形。
- 用户库（`protoroute-pin-profiles`）目前只有 `PinProfile`：脚数、逻辑名→物理脚、空闲脚接哪个网络；**没有几何**，所以不能放置。
- 这就是“点击用户库里的 LM324 出不来一个 14 脚 IC”的原因。

## 3. 需求拆解

用户元件至少有三类，不能用同一个模板硬套：

| 类型 | 例子 | 几何特征 |
|---|---|---|
| 标准 IC | DIP-8/14/16、SOP、QFP | 两排/四边，脚距固定；DIP 能直接落板，SOIC/QFP 需要转接 |
| 模块/异形 | 传感器小板、继电器、电池座、DC 座、自定义 PCB | 外形不规则，可能有安装孔、悬空区域、非对称脚位 |
| 连接器/端子 | 排针、螺钉端子、排母 | 单排/多排，脚距可能不是 2.54 |

需要用户定义的量：

- 脚数、每个脚的物理编号；
- 每个脚在板上的位置（网格坐标）；
- 外形轮廓（矩形/多边形）、高度、颜色；
- 安装孔 / 禁布区（后期）；
- 与 `PinProfile` 的关联（型号+封装）；
- 显示名、位号前缀。

## 4. 为什么不做“完备的编程语言”

“用户复制一段提示词给 AI，AI 写代码，软件生成模型”听起来通用，但会带来几个硬问题：

1. **安全**：在客户端执行用户代码要么 `eval`，要么起沙箱。前者不能接受；后者要处理超时、内存、无限循环、DOM/网络访问。
2. **可审核性**：公用库如果要收用户提交，代码比数据难审得多；一个 `while(true)` 或混淆代码就能拖垮审核。
3. **AI 出错率高**：让 AI 写 JSON 的语法错误率远低于写一门新语言；schema 校验能直接指出哪一行错。
4. **版本迁移**：语言一旦发布就有兼容包袱；JSON 可以加字段、忽略未知字段、逐条迁移。
5. **调试成本**：用户看到的是“模型没出来”，而不是“第 7 个脚越界”；声明式数据可以直接定位。

更合适的做法是：**schema 本身就是“语言”**，但只描述数据，不描述控制流。生成器（重复引脚）用固定原语表达，不让用户写循环/函数。若将来确实需要计算，最多加四则运算和范围表达式，仍然不执行任意代码。

> 如果最终一定要“代码”：只允许本地、沙箱 worker、纯函数 `build(): CDM`、超时 + 大小限制，且**永不进入公用库**。这条作为最后的备选，不放进第一版。

## 5. 方案：元件描述清单（CDM）

### 5.1 分层

```
电气层  PinProfile      型号+封装 → 逻辑脚 ↔ 物理脚号、脚数、电源脚
几何层  CDM             型号+封装 → 物理脚坐标、外形、高度
放置层  PlacedComponent 引用 CDM 并把几何快照进工程（工程自包含）
```

- 一个型号可以有多个封装（DIP-14 / SOIC-14），因此 CDM 的身份是 **型号 + 封装**，和 `PinProfile` 一致。
- `PinProfile` 与 CDM 的脚数必须一致；CDM 的物理脚集合应覆盖 `PinProfile` 里所有 `physical`。
- 放置时只认物理脚号；Multisim 的逻辑名解析仍然走 `PinProfile`，两边不重复存映射。

### 5.2 Schema 草案

```json
{
  "schemaVersion": 1,
  "id": "lm324d@case751a",
  "source": "user",
  "identity": { "value": "LM324D", "package": "CASE751A" },
  "display": {
    "label": "U",
    "title": "LM324D",
    "color": "#1f2937",
    "refPrefix": "U"
  },
  "pinCount": 14,
  "origin": [0, 0],
  "body": {
    "shape": "rect",
    "x": -0.5,
    "y": -0.5,
    "width": 4,
    "height": 7,
    "heightMm": 4,
    "cornerRadius": 0.2
  },
  "pins": [
    { "number": 1, "at": [0, 0] },
    { "number": 2, "at": [0, 1] },
    { "number": 3, "at": [0, 2] },
    { "number": 4, "at": [0, 3] },
    { "number": 5, "at": [0, 4] },
    { "number": 6, "at": [0, 5] },
    { "number": 7, "at": [0, 6] },
    { "number": 8, "at": [3, 6] },
    { "number": 9, "at": [3, 5] },
    { "number": 10, "at": [3, 4] },
    { "number": 11, "at": [3, 3] },
    { "number": 12, "at": [3, 2] },
    { "number": 13, "at": [3, 1] },
    { "number": 14, "at": [3, 0] }
  ],
  "holes": [
    { "at": [1.5, 3], "diameterMm": 3.2 }
  ],
  "keepouts": [],
  "packagePitchMm": 2.54,
  "notes": ""
}
```

约束：

- `pins[].at` 必须是整数网格坐标；`body` 可以是小数网格（只影响显示/碰撞）。
- `origin` 是放置锚点，默认 `[0,0]`；脚 1 建议放在 `[0,0]`，但不是强制。
- `pinCount` 与 `pins.length` 必须一致，脚号 1..N 不重复。
- `packagePitchMm` 只用于提示“这个封装能不能直接落板”：不是 2.54 时，落板前应要求转接板或阻止。
- 所有长度单位默认是网格（1 = 2.54 mm）；`*Mm` 字段明确是毫米。UI 同时显示毫米。

### 5.3 外形

第一版只支持：

- `rect`：矩形（可圆角），覆盖 80% 模块；
- `polygon`：简单多边形（不允许自交、不允许洞），用于异形板/座子。

暂不支持：曲线、多个独立 body、3D 网格。以后可以加 `mesh`（STL/GLB）作为独立类型，几何仍只用于显示和粗略碰撞。

### 5.4 生成器与规范化

手写 14 个脚太啰嗦，允许在“编辑输入”里用固定生成器，**保存时展开成显式 `pins`**，运行时不再解释生成器：

```json
"pinGroups": [
  { "kind": "line", "from": [0, 0], "step": [0, 1], "count": 7, "startNumber": 1 },
  { "kind": "line", "from": [3, 6], "step": [0, -1], "count": 7, "startNumber": 8 }
]
```

支持的生成器（够用即可）：

| kind | 参数 | 用途 |
|---|---|---|
| `line` | from, step, count, startNumber | 单排、两侧各一排 |
| `grid` | rows, cols, rowGap, colGap, startNumber, order | 矩阵排针、BGA 风格 |
| `dualRow` | count, rowGap, startNumber | DIP 数字编号（1..N/2 顺排，N/2+1..N 逆排） |

生成器只做坐标/编号展开，不做条件、循环变量、表达式。保存后 `pins` 是唯一事实来源。

### 5.5 校验

保存/放置前必须过：

1. `pins` 非空、脚号 1..N 连续无重复；
2. 坐标是整数网格，且在板内（放置时再校验）；
3. `pinCount === pins.length`；
4. `body` 是合法矩形/简单多边形，面积 > 0；
5. `holes` 不与引脚孔重合；
6. `packagePitchMm !== 2.54` 时给出“需要转接板”警告，不默认允许直接落板；
7. 与 `PinProfile` 的物理脚集合一致（有 profile 时）。

放置时还要过：

- 每个脚落在合法孔位、不与其他元件共孔；
- body 的包围盒在板内（异形悬空是否允许，见开放问题）；
- 与已有元件 body 的重叠（第一版只警告，不做复杂多边形碰撞）。

## 6. 从 PinProfile 提取

用户库里的 LM324D 已经有：

```
pinCount = 14
pins: 1OUT=1, 1IN-=2, ..., VS+=4, VS-=11
package = CASE751A
```

“提取为可放置元件”时：

1. 按封装名选模板：`DIP/PDIP → DIP 几何`；`SOIC/SOP → 双排但 pitch 1.27 mm`；`QFP → 四边`；都不匹配 → 空模板；
2. 生成一个 CDM 草稿（14 个脚、默认外形、脚号 1..14）；
3. 如果封装 pitch 不是 2.54 mm，提示“直接插洞洞板不成立”，建议：
   - 用转接板（复用现有 `AdapterSpec`），或
   - 只把这个 CDM 当作外形参考，不落板；
4. 用户确认/修改外形和脚位，保存到用户库；
5. 之后在元件库“用户”页点击该条目即可放置。

注意：**提取不等于自动正确**。DIP 的脚位是标准的，但“SOIC 的 1 脚在哪”“模块的排针朝哪边”都可能要用户确认；模板只是草稿。

## 7. 公用库与用户库同形

最终两者都用 CDM：

```json
{ "schemaVersion": 1, "id": "dip14", "source": "builtin", "kind": "dip", ... }
```

- 内置元件可以先保留现有 `LibraryComponentDefinition`，在适配层转成 CDM；迁移完成后再删旧结构；
- 用户库、公用库共用：
  - 同一个详情/预览组件；
  - 同一个放置流程；
  - 同一个校验器；
  - 同一个导出格式。
- 区别只在 `source` 和审核状态：
  - `builtin`：随包发布，只读；
  - `user`：本机，可编辑/删除/导出；
  - 将来 `community`：提交后审核通过，随包发布（需要单独的审核工具，不能和引脚配置混在一起）。

**用户提交几何比提交引脚表风险高**：多边形可能巨大、坐标可能越界、外形可能恶意重叠。公用库的几何提交必须限制大小、做 schema 校验，并人工预览。

## 8. 放置与渲染

### 8.1 数据

`PlacedComponent` 增加一个可选的几何快照：

```ts
interface CustomGeometry {
  manifestId: string;      // 来源，仅用于“回到库中编辑”
  body: BodyShape;
  pins: Array<[number, number]>;
  heightMm: number;
  color?: string;
}
```

- 放置时把 CDM 解析成 `pinOffsets` 和 `customGeometry` 存进元件；
- 工程 JSON 因此自包含：库条目被删/改了，已放置元件不变；
- `pinOffsets` 仍是布线和 DRC 的唯一来源，`customGeometry` 只给渲染和外形校验用。

### 8.2 渲染

- 2D/3D 都用 body 轮廓挤出（矩形直接 box，多边形 extrude）；
- 引脚仍然画成圆柱/方块，落在网格孔上；
- 高度、颜色来自 CDM；
- 第一版不做贴图、丝印、倒角；以后可接 mesh。

### 8.3 规则

- `kind: "custom"` 走通用规则：脚在孔上、body 在板内、孔不冲突；
- 不再套用 DIP 的“跨中缝”“两脚元件跨中缝”等专用规则（除非 CDM 显式声明 `kind: "dip"`）；
- 布线端点、网表解析、DRC 完全复用现有 `pinOffsets` 逻辑，不需要改路由。

## 9. AI 工作流

固定三步，全部在本地完成：

1. 应用里点“复制提示词”，内容包含：
   - schema 版本；
   - 坐标/单位规则；
   - 两个完整示例（DIP-14、异形 3 脚模块）；
   - “只输出 JSON，不要解释”；
2. 用户把数据手册的引脚表/尺寸粘给 AI，AI 返回 JSON；
3. 用户粘回编辑器 → 校验 → 3D 预览 → 保存。

提示词只描述数据格式，不描述代码。校验失败时给出精确路径，例如：

```
pins[7].at 必须是整数网格坐标
pinCount=14，但 pins 有 12 个
脚 9 与脚 10 坐标重复
```

这样 AI 可以按报错重试，不需要理解整个应用。

## 10. 可视化编辑器（主路径）

不是所有人都愿意和 AI/JSON 打交道。最小编辑器：

- 选模板（DIP / 双排 / 单排 / 矩形模块 / 空白）；
- 在网格上点孔加脚，自动编号；拖动可改脚位；
- 拖矩形四角改外形；多边形点选顶点；
- 填高度、颜色、脚距提示；
- 右侧实时 2D/3D 预览；
- “从 PinProfile 提取”按钮生成草稿；
- “导出 JSON / 导入 JSON”用于备份和分享。

AI 只是“批量填表”的快捷方式，不是唯一入口。

## 11. 安全与审核

- 第一版只接受数据，不接受代码；不 `eval`、不加载远程脚本；
- JSON 大小上限（例如 256 KB）、引脚数上限（例如 256）、多边形顶点上限（例如 64）；
- 坐标/尺寸做数值范围校验，拒绝 NaN/Infinity/超大数；
- mesh（未来）限制文件大小、三角面数，解析在 worker 里；
- 公用库提交：单独的审核流程，预览图 + 原始 JSON，不自动合并；
- 用户库只在本机，不参与匿名回流（除非以后单独设计）。

## 12. 分阶段

| 阶段 | 内容 | 依赖 |
|---|---|---|
| P0 | CDM schema + DIP/矩形模板 + 从 PinProfile 生成草稿 + 放置/渲染 + 用户库可点击放置 | 现有 `library.ts`、`PinProfile` |
| P1 | 可视化编辑器 + 校验 + 导入/导出 + 删除/编辑 | P0 |
| P2 | 多边形外形、安装孔、简单 body 碰撞警告 | P1 |
| P3 | AI 提示词 + JSON 粘贴 + 报错回填 | P1 |
| P4 | 非 2.54 封装的转接板联动 | P0/P2 |
| P5 | mesh（STL/GLB）+ 云端/公用库提交审核 | P2/P4 |

P0 的关键验收：用户库里的 LM324D 点一下能放出一个 14 脚 DIP，脚位与 `PinProfile` 的物理脚号一致，布线/DRC 全部照常工作。

## 13. 开放问题

1. **异形 body 允许悬出板边吗？** 例如 DC 座、电池座。若允许，DRC 的“板内”规则要放宽到“引脚在板内 + body 可悬出”。
2. **非 2.54 间距怎么处理？** 一律要求转接板，还是允许“仅显示、不可落板”的元件？
3. **多体元件**：一个模块带一块小 daughterboard，算一个 body 还是两个？
4. **脚位是否允许非整数网格？** 若允许，布线会失去孔位语义；建议第一版禁止。
5. **公用库几何要不要允许用户提交？** 审核成本高，可能先只做本地用户库。
6. **内置库何时迁移到 CDM？** 先适配层并存，还是直接重写 `componentLibrary`？
7. **3D 精度**：挤出轮廓够不够，还是必须 mesh？
8. **AI 生成失败的责任**：只提示“校验失败”，还是提供“用默认模板继续”的降级路径？

## 14. 暂不做

- 图灵完备的元件脚本语言 / 任意代码执行；
- 曲线、丝印、贴图、真实 3D 模型（第一版）；
- 用户几何的匿名回流与自动合并；
- 多层板、非洞洞板基板；
- 自动从数据手册 PDF 提取引脚表。
