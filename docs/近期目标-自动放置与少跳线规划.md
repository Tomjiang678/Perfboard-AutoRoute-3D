# 近期目标：7月10日前完成稳定可用的自动放置与少跳线优化

## 时间目标

目标日期：2026年7月10日前。

目标状态：稳定用于真实项目，而不是只做演示。自动放置结果应能支撑后续自动布线，并以跳线数量最少为核心优化目标。

## 核心判断

自动布线理论上不应“失败”，因为底面走线、跳线、必要时更激进的元件姿态调整共同构成完整搜索空间。因此近期目标不再以“是否布通”为主要指标，而是以以下顺序优化：

1. 跳线数量最少。
2. 底面走线尽量短、少交叉、少拥塞。
3. 元件布局仍然可焊接、可读、可维护。
4. 斜插和跨越其它元件作为代价较高的手段，但优先级仍高于使用跳线。

## 放置自由度

### 允许脚距微调的元件

只允许 2 个引脚的小元件参与脚距微调。

允许：

- R：电阻。
- L：电感。
- C：普通电容。
- diode / LED：二极管和 LED。

不允许：

- 3 个及以上引脚的元件。
- DIP、IC、排针、端子、电位器、按键等多引脚或结构约束强的元件。

### 脚距范围

脚距调整先写死在算法中，不做 UI。

建议默认范围：

- 电阻、电感、轴向电容：2 到 5 格。
- 二极管、LED：2 到 4 格。

脚距微调的代价较低。为了减少跳线，可以积极接受脚距变化。

### 任意角度斜插

允许小元件任意角度斜插，但必须满足：

- 每个引脚必须落在洞洞板孔位上。
- 引脚不能占用其它元件已经占用的孔。
- 元件本体可以从正面跨过其它元件。
- 跨越不代表电气连接，只有引脚落孔和底面连接参与电气图。

斜插不限制为 45 度。算法上可表达为”两个引脚选择任意合法孔位，元件本体按引脚几何姿态渲染”。

斜插属于高代价策略，但仍优先于跳线。优先级建议：

1. 常规水平/竖直放置。
2. 水平/竖直放置 + 小元件脚距微调。
3. 任意角度斜插。
4. 跳线。

> **斜插和脚距微调均只允许 2 引脚元件参与。**

## 算法实施方案

### 1. 元件放置候选生成

为每个元件生成候选姿态。

多引脚元件：

- 保持现有水平/竖直旋转。
- 不做脚距变化。
- 不做斜插。

小元件：

- 生成默认水平/竖直姿态。
- 生成脚距微调后的水平/竖直姿态。
- 生成任意合法孔位组合形成的斜插姿态。

候选需要包含：

- 每个引脚的 grid 坐标。
- 元件本体的近似占用/跨越区域。
- 是否斜插。
- 是否改脚距。
- 脚距变化量。
- 与其它元件本体的正面跨越关系。

### 2. 占用规则

硬约束：

- 引脚孔位不能重复占用。
- 引脚必须在板内。
- 4 个及以上引脚元件不允许被改变封装几何。
- 元件不能放到板外。

软约束：

- 小元件本体可以跨越其它元件。
- 跨越其它元件增加代价，但不判为非法。
- 跨越数量越多，代价越高。
- 斜插代价高于普通脚距微调。

### 3. 放置评分函数

放置评分应直接面向最终布线质量，而不是只看局部整齐程度。

建议评分项：

- `jumperCount * veryHighCost`
- `jumperLength * highCost`
- `failedNetCount * extremeCost`，理论上应为 0，但保留用于防御。
- `bottomTraceLength * mediumCost`
- `routeCongestion * mediumCost`
- `bendCount * lowCost`
- `diagonalPlacementCount * highCost`
- `bodyOverpassCount * mediumHighCost`
- `leadStretchPenalty * lowToMediumCost`
- `layoutCompactnessPenalty * lowCost`

关键原则：

- 跳线成本最高。
- 斜插和跨越其它元件成本高，但低于跳线。
- 脚距微调成本较低。
- 为了减少跳线，可以接受明显脚距变化和少量斜插。

### 4. 搜索流程

近期目标采用分阶段搜索，先保证可实现和可调试。

第一层：常规自动放置

- 使用现有自动放置逻辑生成初始结果。
- 运行自动布线。
- 记录跳线数量、跳线长度、拥塞热点和失败/困难网络。

第二层：小元件局部重排

- 找出与跳线相关的网络。
- 找出这些网络上的小元件。
- 对这些小元件生成脚距微调候选。
- 局部替换放置并重新布线。
- 保留评分更优的结果。

第三层：任意角度斜插搜索

- 仍以跳线相关网络为搜索重点。
- 对小元件尝试任意角度引脚落孔组合。
- 优先尝试能缩短关键网络曼哈顿距离、避开拥塞区、减少跳线端点冲突的候选。
- 每次候选变更后运行布线评分。

第四层：跳线兜底

- 若所有合理放置候选仍需要跳线，则保留跳线最少、总长度最短的方案。

### 5. 性能控制

任意角度斜插候选可能爆炸，必须限制搜索范围。

限制策略：

- 只对跳线相关网络上的小元件开放斜插。
- 只在元件当前位置附近一定半径内搜索。
- 先按网络端点距离筛掉明显差的候选。
- 每轮只优化最影响跳线数量的前 N 个小元件。
- 设置总候选评估预算，避免 UI 卡死。

## UI 视觉一致性约束

斜插和脚距微调会改变元件在板上的几何形态。以下情况必须严格避免，否则用户体验无法接受。

### 硬性禁止（出现即为未完成）

#### 1. 引脚与本体脱节

元件的视觉本体（丝印/3D 体）必须与引脚实际位置匹配。

- 电阻、电感、二极管等轴向元件：本体长度方向应随 `leadSpacing` 等比拉伸，本体两端分别靠近两个引脚孔位。
- 电容等径向元件：本体中心与引脚中心对齐，本体不应覆盖引脚孔位以外的区域。
- **禁止**：引脚孔位出现在视觉本体之外（"引脚悬空"）。

#### 2. 斜插元件本体方向与引脚连线不一致

斜插元件的视觉本体必须旋转到与两个引脚孔位连线一致的角度。

- 本体长轴方向 = 两引脚孔位的连线方向。
- **禁止**：本体方向仍保持水平或竖直，而引脚孔位却在对角位置（"拧麻花"）。

#### 3. 引脚孔位不可见或被遮盖

无论元件是否斜插、是否跨越其它元件，引脚所在的洞洞板孔位必须对用户可见。

- 选中的元件：引脚孔位必须以高亮圈/标记突出显示。
- 未选中时：引脚孔位至少应可见（不能被本体完全遮盖导致无法辨认落孔位置）。
- **禁止**：引脚孔位被本体渲染完全遮挡，用户无法判断引脚落在哪个孔。

#### 4. 正面跨越不能与底面走线混淆

元件本体从正面跨越其它元件 ≠ 底面电气连接。UI 必须让用户一眼区分以下三个层次：

- **顶层**：元件本体、正面跨越（允许，属于物理放置）。
- **孔层**：引脚落孔。
- **底层**：底面走线、跳线（属于电气连接）。

建议手段：
- 本体跨越时使用**半透明渲染**或**虚线轮廓**。
- 底面走线和跳线使用独立颜色层（如蓝色/红色），与本体层明显区分。
- 跨越区域不做自动 DRC 报错标记。

**禁止**：正面跨越在视觉上与底面短路难以区分。

#### 5. 元件本体不能穿模重叠

即使正面跨越允许，两个元件的 3D 本体也不能在同一空间重叠（穿模）。

- 本体跨越 = 高处跨过，不占用被跨越元件的本体空间。视觉上应有高低之分或有明显间隙。
- **禁止**：两个元件的本体渲染在视觉上重叠、交错、插入对方空间（"穿模"）。

#### 6. 选中/高亮不能覆盖真实几何

斜插或改脚距后的元件，选中框（selection highlight）必须反映真实几何：

- 斜插元件：选中框应旋转对齐本体方向，或使用最小包围矩形但需包含旋转后的完整本体。
- 改脚距元件：选中框尺寸必须反映变更后的本体尺寸。
- **禁止**：选中框使用库默认尺寸和角度，与实际放置不一致。

#### 7. 属性面板数值必须与实际一致

当用户选中一个被自动放置修改过的元件时，属性面板（Inspector）必须反映实际值：

- `leadSpacing` 显示实际脚距（而非库默认值）。
- `rowSpacing` / `sameSidePitch` 同理。
- 旋转角度显示实际角度（斜插可能不是 0°/90°/180°/270°）。
- **禁止**：属性面板显示库默认值但实际放置已经是修改后的值（"数据不一致"）。

#### 8. 孔位占用标记必须准确

洞洞板上已占用的孔位标记必须基于**实际引脚落孔位置**计算。

- 改脚距后，两个引脚的实际落孔间距改变，占用标记需要更新。
- 斜插后，引脚落孔不再在水平/竖直线上，占用标记需要准确反映。
- **禁止**：占用标记仍基于库默认引脚位置，导致后续放置冲突或误导用户。

### 软性建议（可按优先级逐步实现）

- 斜插元件渲染时附带浅色的引脚连线辅助线，帮助用户看清方向。
- 体跨时对底层元件加虚线轮廓或降低不透明度，表明它被覆盖但仍存在。
- 自动放置运行后提供变更摘要（哪些元件改了脚距、哪些斜插了）。
- 支持撤销自动放置变更，恢复原始姿态。

## 风险

- 任意角度斜插会显著扩大搜索空间，需要严格候选剪枝。
- 元件本体跨越其它元件会增加 3D 渲染和可读性复杂度，需要视觉上明确区分正面跨越和底面连接。
- 跳线成本过高可能导致算法过度使用斜插，需要用项目样例校准权重。
- 改脚距后本体拉伸、斜插后本体旋转、跨体半透明等 UI 改动涉及渲染管线，工作量可能超出预期。
- 属性面板显示实际值而非库默认值需要改动数据流，要保证编辑/撤销/序列化一致。

## 非目标

近期不做 UI 配置项。以下参数先写死在算法里：

- 哪些元件允许脚距微调。
- 各类小元件脚距范围。
- 是否允许斜插。
- 斜插代价。
- 跨越其它元件代价。
- 候选搜索预算。

近期不支持：

- 3 个及以上引脚元件变形。
- 芯片斜插。
- 引脚不落孔的任意角度放置。
- 正面跨越导致的自动机械避让建模。
